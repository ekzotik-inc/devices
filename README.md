# CRM Device Import · Генератор

Современное веб-приложение для подготовки файлов импорта устройств в CRM.
Главная задача — автоматически сформировать готовый CSV-файл, **на 100%
совместимый по структуре с загруженным эталонным шаблоном CRM**.

## Главное правило проекта

CSV **никогда не генерируется «по памяти»**. Структура итогового файла
полностью определяется загруженным пользователем шаблоном:

- те же названия колонок;
- тот же порядок колонок;
- тот же разделитель полей;
- та же кодировка (UTF-8, с BOM или без — как в шаблоне);
- то же расширение файла;
- тот же формат переноса строк (CRLF/LF);
- то же экранирование кавычками.

Если структура шаблона меняется — приложение автоматически определяет новую
структуру и использует именно её. Отсутствующие поля остаются **пустыми**, а
не удаляются.

## Возможности

- **Drag & Drop** загрузка шаблона CRM (CSV) и файла устройств (Excel `.xlsx`
  или CSV).
- **Анализ структуры** шаблона: колонки, порядок, разделитель, перенос строк,
  BOM, формат даты.
- **Автоматическое сопоставление** колонок исходного файла с шаблоном + ручная
  корректировка.
- **Полная валидация**: обязательные колонки и поля, дубли кодов устройств,
  пустые значения, неверный формат `packing_date`, лишние пробелы, количество
  строк. Понятные сообщения и скачиваемый отчёт об ошибках.
- **Предпросмотр** итоговой таблицы с поиском, сортировкой, фильтрацией,
  пагинацией и счётчиком записей — видно именно то, что будет выгружено.
- **Экспорт** CSV строго по структуре шаблона.
- **Производительность**: тяжёлый разбор и обработка вынесены в Web Worker —
  интерфейс не зависает на файлах 10 000 / 50 000 / 100 000 строк.
- **UX**: индикатор загрузки, прогресс обработки, уведомления, журнал ошибок.
- Адаптивная вёрстка в фирменном минималистичном стиле IQOS.

## Архитектура (модули)

`src/modules/`:

| Модуль | Назначение |
| --- | --- |
| `fileLoader.ts` | загрузка и чтение файлов (CSV/Excel) |
| `structureAnalyzer.ts` | чтение шаблона и анализ его структуры |
| `dataProcessor.ts` | сопоставление и обработка данных |
| `validator.ts` | проверка данных |
| `csvExporter.ts` | экспорт CSV строго по шаблону |
| `dataWorker.ts` | фоновая обработка (Web Worker) |
| `workerClient.ts` | обёртка обмена с воркером |
| `types.ts` | общие типы |

UI: `src/components/` (DropZone, StructureCard, MappingPanel, ValidationPanel,
PreviewTable, ProgressBar, Toast).

```bash
npm run dev      # режим разработки
npm run build    # сборка в dist/
npm run preview  # просмотр сборки
```

## Деплой (GitHub Pages)

В репозитории настроен workflow `.github/workflows/deploy.yml`, который при
пуше в рабочую ветку (или `main`) собирает приложение и публикует его на
GitHub Pages.

**Однократный шаг (нужен один раз):** включите Pages в настройках
репозитория —
`Settings → Pages → Build and deployment → Source = «GitHub Actions»`.
Токен GitHub Actions не имеет прав создавать сайт Pages автоматически, поэтому
первый раз источник выбирается вручную. После этого каждый пуш деплоит сайт
сам.

Запустить деплой можно также вручную: `Actions → Deploy to GitHub Pages → Run
workflow`. Адрес сайта появится в логе шага deploy и в `Settings → Pages`
(обычно `https://<owner>.github.io/devices/`).
